# PBP Common

The first-stage PBP shared by the image's PBP slots, one chip per build:

* **`d13x` (default)** — the `image.updater.psram` and
  `image.updater.bootloader` updaters and the flash-resident bootloader. It
  brings PSRAM up only when it is not already up, then either jumps to the
  bootloader or, in the `image.updater.psram` role, returns to its caller (the
  D13x PBP entry is return-capable).
* **`d21x`** — the D21x first stage, in two rounds for a host-driven start. The
  BootROM's downloader runs it first as `image.updater.ddr`: bring the DRAM
  controller up, then `return` to the BootROM (the D21x PBP entry is
  return-capable and restores the caller's registers and CSRs). It runs it a
  second time as the bootloader updater (`image.updater.bootloader`), with DRAM live and the bootloader's
  container in DRAM: load that container's loader and jump to it with the
  upgrade role. A flash start instead loads the bootloader's AIC container from
  the SPI-NAND boot slot and jumps to it with the boot role.

Build one chip at a time — the SoC features (`d13x`, `d21x`) are mutually
exclusive:

```bash
cargo check -p pbp-common --features d13x --target riscv32imafc-unknown-none-elf
cargo check -p pbp-common --no-default-features --features d21x --target riscv64gc-unknown-none-elf
```

## Build

The board presets in [`boards/`](../../../boards/README.md) point the boot chain's
PBP slots at this crate's **ELF** (`pbp_package = "pbp-common"`) and let `aicfwc`
flatten and wrap it, so nothing has to be copied. From the workspace root:

```bash
cargo run -p aicfwc -- --board d13x-nor --bootloader --build
cargo run -p aicfwc -- --board d21x-nand --bootloader --build
```

(`--app <package>` instead of `--bootloader` packages a product image; the PBP
slots are the same.)

A D21x preset declares `features = ["d21x"]` on the components that use this
crate, which `aicfwc --build` passes as `--no-default-features --features d21x`.
Layout constants (`UPG_BOOTLOADER_SLOT`, `BOOTLOADER_APP_NAME`) are generated by
`build.rs` from `boards/*.toml` into `src/layout.rs`.

To inspect the D13x PBP on its own (not needed for an image):

```bash
cargo build -p pbp-common --target riscv32imafc-unknown-none-elf --release
rust-objcopy -O binary target/riscv32imafc-unknown-none-elf/release/pbp-common target/riscv32imafc-unknown-none-elf/release/pbp-common.bin
cargo run -p aicfwc -- target/riscv32imafc-unknown-none-elf/release/pbp-common.bin --raw-img --spi-nor
```

and the D21x one:

```bash
cargo build -p pbp-common --no-default-features --features d21x --target riscv64gc-unknown-none-elf --release
rust-objcopy -O binary target/riscv64gc-unknown-none-elf/release/pbp-common target/riscv64gc-unknown-none-elf/release/pbp-common.bin
cargo run -p aicfwc -- target/riscv64gc-unknown-none-elf/release/pbp-common.bin --raw-img --spi-nand
```

## D13x notes

* Role detection is hardware-based, not timer-based: PSRAM already decoding XIP
  means the `updater.psram` call preceded us, so this is the `updater.bootloader`
  run — boot the RAM container and do not bring PSRAM up again. Otherwise the
  ROM's downloader is either running (the `updater.psram` service call — return
  to it) or not (a cold boot — bring PSRAM up, then boot the flash container).
* A cold boot also honours the BOOT key, handing the chip to the ROM's upgrade
  entry — the only path that can still replace a corrupt first-stage image.
* The next stage is told its `Role` through `system::{set_role, role}`; the
  identify/copy/jump logic itself lives in `artinchip_hal::system`.

## D21x notes

* **Two updater rounds and a flash start.** A host-driven start
  (`boot_device() == Usb`) runs this image twice. `image.updater.ddr` runs with
  DRAM off: it brings DRAM up, publishes `Role::Upgrade`, and *returns* to the
  BootROM, which then copies the next container into DRAM. The BootROM runs this
  image again as `image.updater.bootloader` — DRAM live, container in
  `UPG_BOOTLOADER_SLOT` (`0x4080_0000`) — and that run resolves the loader out
  of the RAM slot, copies it to its DRAM address, publishes `Role::Upgrade`, and
  jumps. A flash start instead brings DRAM up if needed, loads the installed
  bootloader from the SPI-NAND boot slot, and publishes `Role::Boot`.
* **Stack and `ext_reserve`.** The D21x stack is 6 KiB (plus the 64-byte park
  slot) in NOLOAD `.bss.uninit`, fitting under `ext_reserve = 0x2000` in
  `boards/d21x-nand.toml`.
* **DRAM uses `artinchip_hal::dram`.** Efuse detection (`Dram::detect_type`) and
  preset selection (`DramConfig::for_detected`) live in `artinchip-hal/src/dram/`,
  symmetric with `pbp-dram`.
* **Load source: SPI-NAND, page 1.** Page 0 holds the `AICP` page table and page 1
  starts the AIC container. `src/d21x.rs` wraps `artinchip_hal::spi_flash::SpiNandFlash`
  in `artinchip_hal::system::NandRead` to resolve and copy the nested loader.
